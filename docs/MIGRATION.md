# Переход со старого бота

Эти шаги выполняет владелец при развёртывании. Реальные процессы автоматически
не останавливаются, настройки не меняются и переключение не выполняется.

1. Завершите/разберите текущие задания старого бота. Импорт допускает только
   `sent`, `skipped`, `text_only`. Любые queued, attempted, text_verified,
   неизвестные фазы или незавершённые workflow блокируют весь импорт.
2. Остановите старый процесс и его автоматический перезапуск.
3. Сохраните исходную `.state` и конфигурацию в закрытый backup.
4. Подготовьте новый отдельный volume и импортируйте offline:

   ```sh
   docker compose run --rm --no-deps \
     -v /absolute/backup/state.json:/import/state.json:ro \
     tiktok-gateway import --legacy-state /import/state.json
   ```

   Источник должен быть доступен UID 65532. Команда не использует TikTok и не читает
   cookies. `TIKTOK_ACCOUNT_ID` должен совпадать с `SelfID`. Источник не изменяется.
   Не монтируйте старую `.state` как `/data`.
5. Запустите `docker compose up -d`. После импорта отправки на паузе.
6. Проверьте `/v1/status`, `/readyz`, сессию, каталог стикеров и webhook. Задержанные
   события после старого checkpoint могут прийти в n8n; исходное время сохраняется.
7. Вызовите `POST /v1/control/resume` с API Bearer-токеном.

Импорт выполняется одной SQLite-транзакцией: `Seen`, `Started`, `LastPoll` и полная
история старых jobs в `legacy_jobs`. События outbox и команды из legacy jobs не
создаются. Повтор того же файла определяется по SHA-256 и ничего не дублирует.
Другой файл в уже инициализированную БД не импортируется. Второй процесс с той же
БД блокируется file lock. Нельзя импортировать в работающий gateway.

Для backup: остановите контейнер, сохраните весь volume с правами/владельцем,
затем запустите его. Не копируйте один `gateway.db` во время записи — актуальные
транзакции могут находиться в `gateway.db-wal`. Проверяйте восстановление backup
в отдельном mock-окружении; не запускайте копию с live cookies параллельно.

Возврат к старому боту после новых отправок требует ручной сверки: новый журнал
не переносится обратно автоматически. Не удаляйте новую БД, чтобы «снять» uncertain.
